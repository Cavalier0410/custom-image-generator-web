# Image Studio 前端工作台升级 Brief

这份文档用于后续对话继续推进前端设计。当前代码已回退到稳定版本，本文件只记录方向和约束，不代表这些功能已经实现上线。

## 当前稳定基线

- 页面主体是 `Image Studio` 图片生成工作台，包含参数栏、参考图栏、结果栏和可展开历史栏。
- 案例专区已经做过虚拟网格优化，桌面卡片尺寸保持原有 `repeat(auto-fill, minmax(190px, 1fr))` 逻辑。
- 案例图片已有骨架加载、轻微缩小进入动画、缓存图检测和失败兜底。
- 默认 `Base URL` 为 `https://api.lts4ai.com`。
- 不要改生图接口、模型请求、历史存储、案例数据结构，优先只做前端体验层。

## 设计目标

参考 `21st.dev` 的高级组件质感，但不要照搬。目标是让页面从“表单工具”更像“创作工作台”：主操作更有启动感，素材入口更清楚，模型状态更可读，案例浏览更有引导，提示词输入更像有助手陪跑。

核心原则：

- 保留现有工作台布局，不重做整站。
- 动效服务关键动作，不做满屏装饰。
- 桌面端卡片尺寸和案例虚拟网格不能被破坏。
- 手机端优先保证上下滑动、详情弹层关闭、套用提示词后的滚动恢复。
- 所有新增模块都要能被测试脚本或 DOM contract 验证。

## 模块方向

### 1. 生成按钮动效

目标：把“运行”按钮做成页面主动作，不只是普通按钮。

建议：

- 按钮内部拆成图标、文案、轻微光感层。
- 空闲态有很弱的光带扫过。
- 生成中显示脉冲或能量流动，但幅度要小。
- 禁用态保持克制，不要让用户误以为可以点击。

避免：

- 不要做强烈霓虹或持续大闪烁。
- 不要让按钮高度变化，避免参数栏跳动。

### 2. 参考图上传区

目标：让上传区像“素材入口”，不是普通文件框。

建议：

- 拖拽进入时显示边框高亮和柔和背景变化。
- 上传区下方增加状态轨，显示 `已上传数量 / 上限`。
- 缩略图列表保持现有逻辑，继续支持添加、选择、删除。
- 有图片时，上传主区域仍然展示当前选中参考图。

避免：

- 不要把上传区变成复杂素材管理器。
- 不要影响当前最多 12 张参考图的限制。

### 3. 模型选择卡片

目标：模型选择不只是下拉框，还能让用户知道当前模型处于什么状态。

建议：

- 保留下拉选择和刷新按钮。
- 在下拉框下面加一个模型状态卡片。
- 卡片展示当前模型名、协议类型、画质、比例等标签。
- 未获取模型时显示“先刷新模型列表”一类的空状态。

避免：

- 不要让模型卡片占用太高空间。
- 不要编造模型能力，只展示当前前端已有数据能确定的信息。

### 4. 案例专区精选横滑

目标：进入案例专区时先看到一排精选案例，降低 442 个案例的浏览压力。

建议：

- 放在案例专区 hero 和搜索栏之间。
- 横向滚动展示 6 到 8 个精选案例。
- 点击精选案例打开现有详情面板。
- 下方原虚拟网格保留，不做分页替代。

避免：

- 不要改变桌面案例卡片大小。
- 不要让精选横滑触发大量图片请求，图片仍然懒加载。

### 5. 提示词输入助手

目标：在用户输入提示词时提供轻量增强入口。

建议：

- 放在提示词文本框下方。
- 先做 4 到 6 个短 chip，例如“增强细节”“产品摄影”“写实质感”“电商主图”。
- 点击后默认追加到当前提示词末尾。
- 未来可以升级成“替换 / 追加 / 改写”三种模式，但第一版不要复杂化。

避免：

- 不要自动改写用户已经输入的内容。
- 不要占用太多参数栏高度。

## 推荐实现顺序

1. 先做提示词输入助手和生成按钮动效，因为它们最影响主流程手感。
2. 再做参考图上传区和模型选择卡片，让参数栏与素材栏的信息更清楚。
3. 最后做案例专区精选横滑，确保不破坏虚拟网格和移动端滚动。

## 验收清单

- `npm test` 通过。
- `npm run build` 通过。
- 桌面端没有横向溢出。
- 案例专区虚拟网格仍只渲染首屏附近卡片。
- 手机端可以正常上下滑动。
- 打开案例详情、关闭详情、套用提示词后，页面滚动恢复正常。
- 生成按钮、上传区、模型卡片、精选横滑、提示词助手都有明确 DOM class，方便 contract 测试。

## 下一轮对话可用 Brief

在当前稳定版 `Image Studio` 上做前端体验升级，参考 `21st.dev` 的高级组件质感，但不要重做整站。需要新增五个方向：生成按钮动效、参考图上传区状态增强、模型选择卡片、案例专区精选横滑、提示词输入助手。硬约束是：不改生图接口、不改案例数据结构、不破坏案例虚拟网格、不改变桌面案例卡片尺寸，手机端必须保持顺滑滚动。先做设计方案和局部原型，再决定是否落代码。
